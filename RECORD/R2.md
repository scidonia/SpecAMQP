- **R2 — the endpoint core**, pure, total, and written against the specification's own vocabulary: a header for the layer it is asked for, then the frame loop over `Spec`'s steps. **The core knows nothing of sockets, and the driver that owns `IO` and calls the boundary lives in its own `lean/Shell/` tree** — not in `lean/Impl/`, because the constraint that nothing there imports `Transport` is what makes "only the boundary module in this directory is not proved" a directory-level fact rather than a reading of the imports, and the driver must import it. The trust gate checks that import half, so a driver placed in `Impl` fails the build rather than quietly falsifying the claim. R1's loopback binaries sit outside for the same reason, with one difference worth keeping straight: they are test tooling, and the shell is the shipped process. The tree name is not decoration — `ledger/ambiguities/transport-close-not-an-input.json` and the transport-close reading both say "the shell owns the consequence", so a reader who has met that phrase knows what lives here.
