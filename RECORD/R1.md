# R1 — the transport shell

> Moved verbatim from `PLAN.md` §23.1 (lines 2085–2092) on 2026-09-25. The boundary
> rationale that motivated authoring our own shim over the stdlib's TCP is in
> `EndpointTrack.md`; the gate is `tests/contracts/r1_transport_shell.sh`.

- **R1 — the transport shell.** A `@[extern]` boundary and its C shim, and a two-process loopback exchange proving that a Lean binary can serve a connection and that the shim neither reorders nor truncates. This is the rung that must come first, because it is the only part whose honesty cannot be checked by building the rest.
  **The surface is six operations, not the four this section first named**, and the skip is the rung's own finding rather than a widening of scope: `accept` cannot be reached without a socket that is bound and listening, and a client cannot dial without `connect`, so `listen` and `connect` are the shortest path to `accept`/`recv`/`send`/`close` rather than additions beside them. What bounds the surface is not a number this document fixes but the gate that pins `@[extern]` to `lean/Impl/Transport.lean` and prints the count — six as of R1 — so a seventh declaration is a visible change in a gate's output and a question for review rather than a quiet addition. The gate's other half checks that nothing else in `lean/Impl` imports the boundary, so "exactly one module here is not proved" is a property of the tree rather than a reading of the imports.

  **R1 is accepted, and how it got there is worth recording because the code never changed.** Two independent review rounds found against the *shell*: first five — an undisclosed `setsockopt` in a disclosure that listed it as absent, a non-resolving path in the trust statement, a short-write branch claimed but unexercised, a stale README claim that the pinned stdlib has no TCP, and the absence of a planner-owned contract so the mutant controls were not reviewable — and then one against the *repair*: the enumeration replacing the absence-list claimed to be exhaustive while omitting the deliberate `EINTR` retries at four call sites, with the shim's header still saying it had "two places it has an opinion". The remedy for the second was not to complete the claim but to **delete it**: the section now states what the code decides, says the list is not a claim about its complement, and leaves "where the two disagree the code is the fact". A reader can check a list against code; they cannot check "every" against anything.

  **The code came through both rounds untouched**, and that is the point: its memory discipline was cleared in the first round — the `recv` allocation, narrowing and ownership transfer, `lean_dec` on the error and EOF paths, `send` returning the kernel's count without retrying — and nothing behavioural changed. What kept failing was the prose *about* the code, three times, and the durable remedy was fewer claims rather than more care.

  **And the controls are evidence now rather than a comment about them.** Three, invocable through `--mutant`, each with its reach pinned per case by `tests/contracts/r1_transport_shell.sh`: `truncating-recv` caught in four cases, `reordering-recv` in three with the empty dialogue *asserted unreachable* because its header is eight zero octets, and `short-send` observing 293 server and 294 client `send` calls where the clean run makes one each — which turns "the Lean loop absorbs a partial accept" from a reading of `sendAll` into a measurement. The controls also caught three defects in the harness that reported them, one of which was a **vacuous pass**: a diagnostic pattern that matched `bind failed`, so a run which never opened a socket was scored as the control being caught. Ports are now derived from the runner's own process id, and a case that cannot bind is reported `INVALID` and can never satisfy a control in either mode.
